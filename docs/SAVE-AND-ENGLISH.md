# 保存后热重载与英文布局修复（1.2.0）

## 英文失效原因与处理

REA 在用户提供的微信输入法 4.0.0 APK 中确认：英文 26 键的 `S3EnglishQwertyKeyboard.f0()` 先执行基类全量布局，再执行 `e3()`；后者通过底行更新再次创建按钮并修正对齐。此前仅监听全量布局构建，第一次互换随后的底行重建会被覆盖。

## 保存流程

- 全部页面底部提供“保存并热重载”。编辑确认、开关、Logo、预设、恢复默认和 JSON/WebDAV 导入只改本地草稿，不再直接改输入法的活动配置。
- 草稿独立存储于 `swipe_symbols_draft`。已保存配置保存在模块私有目录原有的 `swipe_symbols` 文件中，服务连接后不再清空本地副本。
- 保存先同步落盘完整草稿和已保存快照，再通过一次远程 preferences 提交发布全量活动配置及单调递增的版本号。模块仅观察发布版本变更刷新当前键盘；未保存修改不会触发热重载。
- 远程发布失败或服务未连接时，本地保存仍保留，界面明确提示。后续服务连接只补发最后已保存快照，不发布新的未保存草稿；相同活动快照不重复提交。
- 旧版配置从原有远程/本地文件迁移。服务较晚连接时合并旧配置和既有草稿修改，保留未改动的旧键值。导入仍接受原 JSON v1/v2/v3。
- 同包名、同签名的正常覆盖升级会保留 Android 私有文件，从而继承已保存配置；卸载应用或主动清除数据不属于覆盖升级。构建继续使用原有测试签名，并固定输出 `dist/WeType-Flick.apk`。

本地回归覆盖旧版迁移、晚连接合并、未保存不发布、原子发布与删除、离线保存、保存失败、升级及框架配置重建恢复、默认草稿跨进程保留，以及“全量布局后英文底行二次重建”、重复状态更新、嵌套与异常清理。真实 APK 回归确认四个更新点的定位。设备测试代码已编译，尚未完成 LSPosed 真机验证。
